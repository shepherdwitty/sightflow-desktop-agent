## 1. 文档整体概况

### 1.1 产品定位
识流 AI 自称是“基于视觉大模型的智能体系统”，能像真人员工一样“看、想、做”：
- **看**：识别界面内容和用户行为状态。
- **想**：结合业务知识和推理模型做决策。
- **做**：执行回复、提醒、跟进、协同等动作。

它不走微信 API，也不代理登录，主要用在私域运营、客服、销售这类场景。【识流AI运营助手-企业版、识流AI运营助手-国内标准版】

### 1.2 产品版本与形态

| 版本 | 形态 | 关键差异（照文档原文） |
|---|---|---|
| **国内标准版** | Mac 和 Windows 桌面客户端，单机单席位 | 按对话次数扣积分。提示词和知识库都在客户端里配置。不支持自选大模型，也不支持 Coze 或 Dify。【标准版-使用及配置流程 FAQ 6.16】 |
| **企业版**（开放平台 open.thiflow.com） | Web 后台加客户端 | 按算力扣费。可以把算力拆成邀请码，分发给多个客户端。可接入自选大模型（自己的 sk-key）、Coze、Dify。后台统一管理多个客户端的提示词和知识库（企业任务）。【企业版、FAQ 6.16】 |
| **企业尊享版** | 企业版加品牌私有化 | 可以自定义产品名、Logo、客户端图标，生成专属安装包，终端用户看不到识流品牌，还能免费享受后续主版本更新。【识流AI运营助手-企业版 2.4/2.5】 |
| **海外 / WhatsApp 版** | 另有英文 wiki，本次未读 | 英文路线图和英文教程以 WhatsApp 为主。【Feature Roadmap、Intelligent Agent…Tutorial】 |
| **识流 USB 机器人** | 硬件外设 | 用硬件代替软件模拟键鼠，降低账号被弹出或要求重新登录的概率。【识流USB机器人】 |

### 1.3 目标客户
- AI 工具与应用创业者
- 私域服务商、代运营团队
- 为企业做 AI 解决方案的开发者
- 想快速落地 AI 提效的企业【识流AI运营助手-企业版 §3】

标准版面向的是个人和中小商家，比如花店客服、销售。

### 1.5 产品演进时间线（据「识流AI-更新动态」和英文路线图的表格）
- **2025-05**：V0.1 和 V0.5 发布并开放内测，用纯视觉方案识别桌面微信。
- **2025-07～09**：V0.7 系列。加入未读消息自动回复、特定任务、长期任务、知识库、快速和深思两种模式、提示词模板、一键优化提示词、收藏夹发送、Coze 工作流。
- **2025-10/11**：V0.8 和 V1.0。加入主动切换窗口回复、深思模式的“多智能体协作”（记忆历史聊天）、自动更新客户端。
- **2025-12**：V1.1。可以像人一样操作电脑；推出自动模式和辅助模式；接入 Gemini。
- **2026-01/02**：开放平台上线，支持自选大模型、品牌自定义、兑换码自由定价售卖、Coze 和 Dify 接入。客户端加入长消息自动分段发送、一键呼叫人工、与 OpenClaw 打通。
- **2026-03**：V1.2.0。加入客户阶段识别、主动触达加运营报告、辅助模式点踩反馈、每日自动复盘。
- **2026-04**：V1.2.2 加入黑白名单、群里只回 @、转人工、任务置顶。V1.2.405 支持企微和飞书机器人接收转人工提醒。
- **2026-06**：V1.3.1 可配置主动触达的沉默时间和触达时段、展示用户画像、查看和导出历史聊天。企业版加入「企业任务管理」。
- **2026-07**：V1.5.0 上线对话模式，用对话就能生成和修改智能体，改配置前先给确认卡。企业可以加购多个自定义客户端。
- **2026-09**：V2.0 支持多个 IM 场景：微信、企业微信、小红书、抖音、闲鱼、WhatsApp、Line；实验室阶段支持 Boss、QQ、千牛、TikTok。

## 3. 开源版补齐优先级建议（Top 8）

1. **按会话存储的多轮记忆，加深思和极速两档**（B1、B2）
   - 识流的工作流接口已经把“最近 20 条 `{nickname, content}`”定成了标准输入，这也是回复质量差距最大的地方。
   - 做法：用会话标题作 key，把每轮 VLM 读出来的消息和 AI 回复存进 SQLite，下次带上最近 N 条文本。成本几乎不涨，因为都是文本 token。
   - 有了这个，后面的画像、主动触达和工作流接入才有基础。
2. **知识库（RAG），绑定到智能体**（C1、C2）
   - 这是商业化客户最常问的能力。识流的限制是 10M × 30 个文件，可以对标。
   - 方案：本地解析 PDF、Docx、Markdown，切分后用 embedding 做向量检索（sqlite-vec 或 LanceDB），每次只注入 Top-K 段落，只在深思档启用。
3. **回复范围控制：黑白名单、群里只回 @、不回复判断**（B5、B8、B9）
   - 难度低，收益高，能直接降低误回和封号风险，也能减少群消息太多时回不过来的压力。
4. **转人工，加 webhook 通知**（B10）
   - 关键词、死循环和情绪等规则触发后，暂停这个会话的 AI，并推送到企微群机器人或飞书 webhook。
   - 实现是一个 HTTP POST 加上按会话的暂停状态，很便宜，又是 ToB 客户必问的功能。
5. **辅助模式（半自动），加点赞和点踩反馈**（B3、C7）
   - 只生成回复不发送，由人确认。点踩的原因直接写进现有的经验卡片。
   - 这能复用我们已经有的工作记忆，又能让客户放心试用。
6. **Coze、Dify 和 OpenAI 兼容的 Provider**（F1、F2、F3）
   - 现在的 Provider 插件机制已经够用。可以照识流的字段规范（输入 `input`、输出 `output`）写 2 个 Provider，再加一个通用 OpenAI 兼容 Provider，一共几天工作量，马上就能对齐企业版的开放接口能力。
7. **智能体管理加提示词模板、一键优化提示词**（C1、C3、C4）
   - 把单个文本框改成多个智能体，每个都有提示词、知识库、名单和转人工规则，同时只启用一个；再加上模板库和“AI 帮我优化”按钮。这是后面做对话模式（C5）的前置。
8. **特定任务和自动触发规则：图片和素材发送、定时发送**（B7、D1、D3）
   - 先做“命中关键词就发图片或固定话术”和“在当前会话一键发送素材”，比较容易。
   - 带联系人搜索的定时群发，以及主动智能（D4），放到有了按会话记忆之后再做。

> 暂缓的：
> - 多 IM 平台适配、USB 硬件、品牌打包和分发后台：工作量大，或者属于商业化基础设施，等核心回复质量追平之后再做。
> - 邀请码和算力分发：需要服务端和账号体系，要等确定商业模式后再立项。我们已有的 token 账本可以直接作为它的计量底座。
